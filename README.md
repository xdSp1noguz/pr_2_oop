# BIM Collaboration System

Імітаційний прототип системи для співпраці між архітектором, замовником та інженером при роботі з BIM-моделями.

## Структура проекту

```
src/
├── IReviewer.java        - Інтерфейс для рецензування моделей
├── User.java             - Базовий клас користувача
├── Architect.java        - Клас архітектора
├── Customer.java         - Клас замовника
├── Engineer.java         - Клас інженера
├── Model.java            - Клас 3D-моделі
└── BIMCollaboration.java - Головний клас з демонстрацією
```

## Компіляція

Для компіляції проекту виконайте наступну команду з кореневої директорії проекту:

```bash
javac -d build src/*.java
```

## Запуск

Для запуску демонстрації виконайте:

```bash
java -cp build BIMCollaboration
```

## Опис системи

Система демонструє взаємодію між трьома типами користувачів:
- Архітектор публікує 3D-модель та випускає оновлення
- Замовник коментує та затверджує концепт
- Інженер перевіряє конфлікти та надсилає запити на уточнення

## Діаграми UML

Детальна документація та UML діаграми знаходяться в директорії `/docs`:

- `usecase.puml` - діаграма варіантів використання

## Особливості реалізації

1. Використання ООП принципів:
   - Наслідування (User -> Architect, Customer, Engineer)
   - Поліморфізм (інтерфейс IReviewer)
   - Інкапсуляція (приватні поля та методи)

2. Типи зв'язків між класами:
   - Наслідування (User та його підкласи)
   - Реалізація (IReviewer реалізується Architect та Engineer)
   - Агрегація (Engineer має Model)
   - Композиція (Architect створює Model)

3. Відповідність SOLID принципам:
   - Single Responsibility Principle: кожен клас має одну відповідальність
   - Open/Closed Principle: можливість розширення функціоналу без зміни існуючого коду
   - Liskov Substitution Principle: підкласи можуть замінювати базовий клас
   - Interface Segregation: інтерфейс містить тільки необхідні методи
   - Dependency Inversion: залежність від абстракцій, а не від реалізацій
